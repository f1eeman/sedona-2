# Интернационализация: русский, казахский, английский

Дата: 2026-09-18. Статус: согласовано, план не написан.

## Задача

Сайт говорит на трёх языках: русском, казахском и английском. Русский остаётся
таким, какой он есть сейчас, — по адресам, текстам и разметке. Казахский и
английский добавляются рядом.

Донор русскоязычный, переключателя языков у него нет вовсе. Значит это не перенос,
а первое на проекте расхождение с донором такого масштаба, и оно уходит в ADR.

## Решения, принятые до проектирования

Пять развилок закрыты до того, как проектирование началось:

1. **Переводы пишет агент, вычитывает человек.** Смысл донорских фраз переносится,
   а не пересочиняется.
2. **Русский без префикса.** `/`, `/photo/` — русский. `/kk/`, `/kk/photo/` и
   `/en/`, `/en/photo/` — остальные. Текущие адреса не ломаются, `canonical` и
   sitemap уже настроены на них.
3. **Переключатель — в подвале,** отдельной строкой над хэштегом и соцсетями.
   Донорская шапка не трогается: на десктопе она занята впритык — четыре пункта по
   20% плюс 240px под логотип, ровно 1200px, пятый пункт не влезает и ломает
   донорские `nth-child`.
4. **Русские тесты остаются, сверху один новый спек.** Русский стоит на прежних
   адресах с прежними текстами, поэтому семь существующих спеков не трогаются.
5. **Числа донора не пересчитываются.** 2000 остаётся 2000, рубль остаётся рублём,
   переводится только слово-обёртка. Имена авторов фото в английской версии идут
   транслитом, в казахской — кириллицей.

## 1. Маршруты

В `astro.config.mjs`:

```js
i18n: {
  defaultLocale: 'ru',
  locales: ['ru', 'kk', 'en'],
  routing: { prefixDefaultLocale: false },
}
```

Astro маршруты не генерирует — их создают файлы. Страницы переезжают под
рест-параметр:

```
src/pages/[...locale]/index.astro
src/pages/[...locale]/photo.astro
src/pages/[...locale]/form.astro
src/pages/[...locale]/hotels.astro
```

Четыре файла на три языка, а не двенадцать копий. `getStaticPaths` у всех один и
тот же, поэтому живёт в `src/i18n/index.ts`:

```ts
export const localePaths = () =>
  LOCALES.map((locale) => ({
    params: { locale: locale === DEFAULT_LOCALE ? undefined : locale },
  }))
```

Что пустой сегмент действительно исчезает, проверено по коду Astro 7.1.6
(`core/routing/generator.js`): у spread-части берётся `params[name] ?? ''`, пустой
сегмент отбрасывается целиком, а пустой путь превращается в `/`. То есть
`[...locale]/photo` с `locale: undefined` даёт ровно `/photo/`, а не `//photo/`.

**Локаль компоненты спрашивают у `Astro.currentLocale`, а не получают пропом.**
При `prefixDefaultLocale: false` стратегия называется
`pathname-prefix-other-locales`, и в ней `fallbackTo = defaultLocale`
(`core/fetch/fetch-state.js`). Значит на `/` вернётся `'ru'` само, без подпорок.
Прокидывать локаль через шестнадцать компонентов не нужно.

## 2. Словарь

```
src/i18n/index.ts   LOCALES, DEFAULT_LOCALE, isLocale, useTranslations,
                    localeTag, localePaths
src/i18n/ru.ts      источник истины и источник типа
src/i18n/kk.ts      const kk: Dict = { ... }
src/i18n/en.ts      const en: Dict = { ... }
```

Тип выводится из русского: `type Dict = typeof ru`. Оттуда два правила, и оба
работают на одно — забытый перевод должно быть физически нельзя закоммитить.

**Без `as const`.** С ним тип потребовал бы не просто те же ключи, а те же буквы,
и казахский не собрался бы вообще.

**В словаре объекты с ключами, а не массивы.** У `string[]` длина не проверяется:
потерянное пятое преимущество никто не заметит. У объекта пропущенный ключ роняет
`astro check`.

Обращение — полем, а не строкой: `t.reviewForm.submit`, не `t('reviewForm.submit')`.
Опечатка в поле — ошибка типов, опечатка в строке — пустое место в браузере.

Компонент берёт словарь одной строкой:

```ts
const t = useTranslations(Astro.currentLocale)
```

`useTranslations` принимает `string | undefined` (таков тип `Astro.currentLocale`) и
сужает его через `isLocale`, падая на `DEFAULT_LOCALE`.

Рядом живёт `localeTag`: `ru → ru-RU`, `kk → kk-KZ`, `en → en-US`. Он нужен и для
`Intl`, и для `og:locale` (`ru_RU`).

## 3. Данные и подписи разъезжаются

`src/data/*.ts` остаются про структуру, словарь — про текст. Связь по стабильному
ключу.

**У карточек появляется `id`, и он же ключ в словаре.** Не `modifier`, не `width`,
не имя файла картинки: первые два — про CSS, третий — про ассеты, и ключ словаря не
должен от них зависеть.

- `hotels.ts` держит `id`, `title` (имя собственное, не переводится), `price`,
  `rating`, `image`, `facilities`. Подписи типов жилья и инфраструктуры уходят в
  `t.hotels.kinds[kind]` и `t.hotels.facilities[facility]`.
- `features.ts` держит `id`, `image`, `icon`, `modifier`, `width`. Заголовок, номер
  («– №1 –»), текст и `imageAlt` — в словарь.
- `photos.ts` держит `id`, `likes`, `image`, `size`, `shade`. Название и имя автора
  — в словарь.
- `nav.ts` держит `{ key, href }`, где `href` — канонический путь без локали.
  Подпись берётся из `t.nav[key]`, адрес — из `getRelativeLocaleUrl(locale, href)`.

Локальные массивы во фронтматтере `review-form.astro` (`IMPRESSIONS`, `ATTRACTIONS`,
`PERSON_FIELDS`) остаются на месте — разовый блок в `src/data` не выносится, — но
теряют поля `label` и `placeholder`: у них уже есть стабильные `id`, по ним и
ключуется словарь.

### `Layout` худеет с пяти пропов до двух

Сейчас он принимает `title`, `description`, `heading`, `path`, `banner`. Первые три
становятся `t.pages[page]`, четвёртый выводится из `page` через `nav.ts`. Остаётся:

```ts
interface Props {
  page: PageKey
  banner?: 'index' | 'inner'
}
```

Тексты из страниц исчезают полностью: страница говорит, какая она, а не что на ней
написано.

## 4. SEO

`<html lang={Astro.currentLocale}>`.

В `seo.astro` от локали зависят `og:locale`, `inLanguage` у `WebSite`,
`availableLanguage` у `ContactPoint`, а `SITE_NAME` и `legalName` переезжают в
словарь.

Добавляются четыре `<link rel="alternate" hreflang>`: три языка и `x-default` на
русский. Адреса — `getAbsoluteLocaleUrl`, чтобы совпадали с `canonical`.

Для этого `seo.astro` нужен путь без локали. Он у `Layout` уже выводится из `page`
и просто передаётся ниже.

В `sitemap()` включается опция `i18n` — она дописывает в карту `xhtml:link`
с альтернативами:

```js
sitemap({
  i18n: { defaultLocale: 'ru', locales: { ru: 'ru-RU', kk: 'kk-KZ', en: 'en-US' } },
})
```

## 5. Переключатель языков

Отдельной строкой в подвале, над хэштегом и соцсетями. `<nav>` с доступным именем
из словаря и список из трёх пунктов.

**Каждый язык назван на себе** — «Русский», «Қазақша», «English» — и у ссылки стоит
свой `lang` и `hreflang`. Без `lang` скринридер прочитает казахское слово по
правилам русского.

Текущий язык — `<span>`, а не ссылка: так же, как активный пункт меню у донора.

Ссылка ведёт на **ту же страницу**, а не на главную:
`getRelativeLocaleUrl(loc, path)`. Со `/hotels/` — на `/kk/hotels/`.

Что слеш на конце сохранится, проверено: `trailingSlash` по умолчанию `'ignore'`,
формат сборки — `directory`, и `shouldAppendForwardSlash` в этой паре возвращает
`true`. Для русского префикс не подставляется — в `getLocaleRelativeUrl` ветка
`locale !== defaultLocale` просто не срабатывает.

## 6. Скрипты и форматирование чисел

`video.ts` держит четыре русские строки прямо в коде — это нарушает правило проекта
про имена бургера ещё до всякой интернационализации. Они переезжают в разметку
атрибутами `data-player-label-play`, `-pause`, `-sound-on`, `-sound-off`, как уже
сделано с `data-menu-label-open`. Остальные семь модулей текста не содержат и не
меняются.

`hotels-catalog.astro` зовёт `rating.toLocaleString('ru-RU')` с жёсткой локалью.
Становится `localeTag(locale)`: «8,5» в русском и казахском, «8.5» в английском.

## 7. Тесты

Семь существующих спеков не трогаются.

Новый `tests/i18n.spec.ts` проверяет ровно то, чего не видит `astro check`:

- три локали отдают страницу, и `html[lang]` совпадает с ожидаемым;
- на странице четыре `link[rel=alternate][hreflang]`, среди них `x-default`;
- переключатель со `/hotels/` ведёт на `/kk/hotels/`, а оттуда обратно на `/hotels/`;
- по одной переведённой фразе на язык — чтобы поймать словарь, подключённый не туда;
- у ссылок переключателя стоит `lang`.

Полноту словаря проверяет `astro check`, и тест её не дублирует.

`_shots.spec.ts` и `_states.spec.ts` из прогона исключены (`testIgnore: '_*.spec.ts'`)
и запускаются руками. В `_shots` добавляются казахская и английская главная и
страница гостиниц — как самые плотные по тексту.

## 9. Риски

**Казахский длиннее русского процентов на двадцать.** Донор расставлял `<br>`
руками, а перенос заменил их на `width` у абзацев — то есть ширины подогнаны ровно
под русские строки. В казахском и английском текст переломится иначе. Колонка
фиксированная, высоты у текстовых блоков не заданы, так что скорее всего просто
станет на строку больше. Проверяется глазами по `_shots.spec.ts` и правится
точечно; ширины по локалям заводить заранее не нужно.

**`text-transform: uppercase` стоит на `body`.** Английская версия будет целиком
капсом. Это донорский приём, и он не меняется, но по-английски капс читается
крикливее, чем по-русски. Осознанное следствие, а не недосмотр.

**`<br />` в тексте модалки успеха** — донорская подгонка под ширину, а не часть
фразы. В русском она остаётся как есть, в казахском и английском не
воспроизводится: строки там ломаются в других местах.

## 10. Документы

`docs/adr/0006-i18n.md` — трёх языков и переключателя у донора нет, расхождение
такого размера по правилам проекта идёт в ADR. Там же остаются разобранными выбор
адресов, место переключателя и решение не пересчитывать цены.

`CONTEXT.md` получает соответствия терминов: «гостиница», «инфраструктура»,
«отзыв», «достопримечательность», «автор фото» — казахским и английским словом.
Без этого один термин переведут тремя разными словами в трёх местах; глоссарий ровно
от этого и защищает. Раздел про двойное чтение «гостиницы» — каталог против типа
жилья — в переводе требует той же оговорки.

`CLAUDE.md` получает раздел про интернационализацию: где словарь, почему без
`as const`, почему объекты вместо массивов, откуда берётся локаль.

## 11. Что не входит

- Определение языка по браузеру и редиректы. Выбор делает человек, ссылкой.
- Запоминание выбора в `localStorage` или cookie. Язык живёт в адресе, и этого
  достаточно.
- Перевод названий гостиниц и хэштега `#visitsedona` — имена собственные.
- Пересчёт цен в тенге и доллары.
- Логотип и баннер: `Sedona` там часть изображения.
- Четвёртый язык. Конфиг к нему готов, но заводить его сейчас незачем.
